## How to read these numbers (limitations)

- The seeded set was written by the team alongside the engine, so these numbers show regression safety and coverage, **not independent accuracy**. Expect lower results on real content. The held-out probe is the more honest number, and it is still small and written by the same team.
- Precision counts any finding outside `expect` and `also_ok` as a false positive. `also_ok` lists co-triggered findings that are legitimately correct for the text.
- Tone and messaging use a lexicon heuristic when no LLM key is set. It only recognises listed phrases, so subtle tone problems are missed by design.
- Red-team: tightened rules are written only from train variants. The hold-out columns are the measure of generalisation; the train 'after' column only shows the loop works. Paraphrases and misspellings stay open on purpose: matching them by code would flag normal copy.
- Hinglish matching covers spelling variants and Devanagari of phrases an owner has chosen. It does not understand meaning or other Indian languages.
- Hidden-text detection covers white, same-colour-as-background, tiny, off-page, invisible and transparent text, text under images, annotations, metadata, HTML comments, zero-width characters and look-alike letters. Paraphrased instructions and words made only of look-alike letters are known gaps (see the Trust Layer scoreboard).
- Image text is read by local OCR (Tesseract), which can miss small, stylised or low-contrast text; the Proof Pack lists what OCR did not cover.
